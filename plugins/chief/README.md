# Chief

DSH 内的项目管家：通过一个专属 Chief 会话管理多个项目，保留项目原会话供人接手。

## 日常使用

- 点击左侧 **Chief 管家** 进入专属对话；使用独立 preset、管家提示词和工具。
- 右侧箭头展开 **项目看板**，查看控制权、任务、验收、阻碍和下一步。
- Chief 内部工作区默认从分组列表隐藏；会话与磁盘数据保留，搜索入口仍可找回历史。
- 自然语言登记项目，例如“把 /absolute/path/to/project-a 登记为项目 A”。路径须由用户替换。
- 请求调度时说明范围、是否允许修改和验收标准。Chief 可并行委派到不同项目会话。
- 请求“让我直接与项目 A 聊”会切换至该会话，同时暂停该项目的 Chief 调度。

| 命令 | 用途 |
| --- | --- |
| `/home` | 回到 Chief |
| `/where` | 查看当前项目与控制权 |
| `/switch 项目名` | 切换并接手项目 |
| `/resume` | 在项目会话中明确交回 Chief |
| `/resume 项目名` | 指定项目交回 Chief |
| `/resolve 项目名` | 人工核对不确定任务后解除该状态，使用前必须检查实际结果 |

命令选择器第一次 Enter 可能只选中命令，此时再点击发送执行。

## 自动接手与结果

直接在项目会话发送用户消息会自动将该项目设为 user 控制，其他项目不变。
这会阻止后续派发，但**不会自动中断已经运行的任务**；需要中断时使用 DSH 的停止按钮。
`/resume` 只交回调度权，不会自动创建新任务。结果执行完成与验收通过是两个状态。
Chief 需完整读取报告，并核对工具轨迹，才能记录验收。

## 记忆与持久化

默认状态位于 `$DSH_HOME/independent-chief`（无 DSH_HOME 时位于 `~/.dsh/independent-chief`）。
宿主配置 `home` 可指定独立目录。同一目录只能有一个宿主写入者。

0.3.4 修复同一 effect 重叠初始化与卸载后立即重建：复用整套控制器初始化，并等待旧实例的已接纳操作、轮询和存储清理完成后再启动新实例。独立控制器仍不能并行写同一目录。
不增加 SQLite 同步等待时间；同进程重复打开会报告 PID 与目录，跨进程租约冲突保留底层错误。不要删除正在使用的锁文件。
Windows、macOS、Linux 的存储与生命周期回归由 CI 执行；这不等于 Windows DSH Desktop 界面验收。

`memory/` 存放结构化 Markdown 与本地 Git 历史，包含目标、优先级、约束、验收标准、阻碍、下一步。
运行时记忆不会自动推送。离线手工修改前先停止宿主，保留 Markdown 字段结构。
项目控制权、会话映射与任务状态跨重启保存；未知派发不自动重放。

`cordis.patch.yml` 提供 `independent-chief` preset；其 `chief-persona-and-memory` 插件的
`instructions` 可补充管家规则。普通项目使用 Standard preset，不继承 Chief 专用记忆或调度工具。
只有宿主绑定的 Chief 会话拥有调度工具，请从侧栏入口进入，不手动复制 Chief 会话。

## 已知边界

- 最新控制状态不是完整接手事件日志。交回后不能据当前时间线推断历史上从未接手。
- 单状态目录面向一个可信用户，不是多租户权限系统。
- 嵌套侧栏与工作区隐藏使用小范围 DOM/CSS 适配；DSH 升级时需做界面回归。
- 模型仍可能误解或不遵守约束；验收与轨迹提供核对依据，不是执行沙箱。
- 工具覆盖、安装和回滚见 [安装指南](../../docs/installation.md)。
