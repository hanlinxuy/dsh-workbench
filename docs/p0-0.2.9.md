## Chief 与重启

真实模型同时派发 Pi Bot、MLX 两个项目的只读任务，完整回收并读取报告/audit。两份报告超过约定 300 字，Chief 正确记录 `needs_changes`，保存实际超限阻碍和压缩报告的下一步，没有把“执行完成”说成“验收通过”，也没有未经授权再派发。

给 Pi Bot 会话发桌面消息后，Pi Bot 自动成为 user，MLX 仍为 chief。正常重启后 Chief/session IDs、报告、验收、人工控制权、Markdown 记忆保持；`/resume` 明确交回 Pi Bot。再次自然语言要求读记录并切换 MLX，Chief 读取旧结论并实际导航/转人工；`/home` 回到同一 Chief，`/resume MLX` 恢复调度权而不追加任务。

UI 实际观察：左侧 Chief 入口、独立 preset、设置里的 Workbench 环境、TLS 保存反馈、能力提供者列表。套装升级后逐个比对已安装 JS 与 provenance，避免 pnpm 旧 tgz 缓存误报。

## 回归中发现并修复

1. 归属服务晚于 Browser/Git/Desktop 加载，首次 `ctx.get` 会漏登记：改为原生 `ctx.inject` 跟踪服务生命周期。
2. PowerShell 升级后的 previous 路径错误：保留最初配置，恢复时不指回旧包。
3. 仅配置站点路由、没有站点卡时无法发现账号：site_list/site_read 直接返回路由元信息；不返回凭据引用和值，site_verify 仍要求经过审查的业务契约。
4. 测试桥直接执行条件工具被宿主拒绝：使用原生 `tools.resolve`，传入当前 modelSelection 和 toolSet，并释放 admission。
5. 旧“禁止 OPS”测试误把独立运行时包的 scope 当 OPS 插件：改为核对未注册 OPS、未 import OPS，且固定运行时依赖符合要求。

曾有一次测试 Desktop 正常退出超时，在确认 PID、可执行文件及专用 user-data 后终止该测试进程。随后正常重启和模型继续对话通过；未终止正式 Desktop。保留首次浏览器缺 Chrome 的失败记录；最终在任务目录安装独立 Chrome 后重新完成真实截图与会话回归。

## 部署与回滚

安装 `release/core`（内网，无 ChatGPT）或 `release/workbench` 的固定发布提交。原有独立插件仍可使用；不叠加同名提供者。查看 [套装说明](workbench-suite.md)、[能力归属](capability-ownership.md)、[站点与 Cookie](site-cards.md)、[网关契约](../plugins/provider-gateway/README.md)。

升级前停止目标 profile，备份私有状态并记录旧发布提交。Windows 若需退回 0.2.8 或卸载套装，先在环境面板点“恢复原 Shell（卸载前）”，仅恢复 Workbench 管理的路径并关闭自动接入，再正常停止、安装旧固定包、恢复对应状态备份。不要撤销整个账号授权；不要删除文档、索引、项目记忆或会话。TLS 与 provider 选择是当前 profile 原生配置，回滚时恢复对应备份。

当前环境未验证：公司真实 SSO/MaaS/共享池、企业 CA 网络、受限 Windows Desktop GUI、真实外发或远端 merge。交付代码/契约已验收，内网业务接入仍按这些边界做现场确认。
